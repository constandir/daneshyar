# دانشیار — اپ مدیریت دانشگاه (آفلاین، اندروید)

همه داده‌ها فقط روی گوشی ذخیره می‌شن (SQLite). بدون سرور، بدون حساب کاربری، بدون مجوز اینترنت.

## معماری

| بخش | انتخاب |
|---|---|
| رابط | Vite + Preact + TypeScript، فارسی RTL، فونت وزیرمتن داخل بسته |
| ذخیره‌سازی | SQLite واقعی با `@capacitor-community/sqlite` (migration با `PRAGMA user_version`) |
| یادآوری | `@capacitor/local-notifications` (نوتیفیکیشن محلی) |
| بکاپ | `@capacitor/filesystem` + `@capacitor/share` (فایل JSON) |
| اندروید | Capacitor 8 (WebView) |
| ساخت APK | GitHub Actions |

### ساختار پوشه‌ها
```
src/db/schema.ts      جدول‌ها، ایندکس‌ها، migrationها
src/db/driver.ts      درایور SQLite (اندروید) + درایور مرورگر (فقط برای npm run dev)
src/db/repo.ts        لایه دسترسی به داده (CRUD، export/import)
src/store.ts          state سراسری
src/lib/jalali.ts     تقویم شمسی
src/lib/gpa.ts        محاسبه معدل و پیش‌بینی
src/services/notify.ts   زمان‌بندی یادآوری‌ها
src/services/backup.ts   بکاپ/بازیابی
src/pages/            داشبورد، برنامه، کارها، تقویم، بیشتر
.github/workflows/android.yml
```

### یادآوری‌ها چطور کار می‌کنن
- با هر ذخیره/حذف/بازیابی/برگشت به اپ، همه یادآوری‌های قبلی لغو و از روی دیتابیس دوباره ساخته می‌شن؛ پس ویرایش و حذف هیچ یادآوری قدیمی باقی نمی‌ذاره.
- کلاس‌های هفتگی برای ۱۴ روز آینده زمان‌بندی می‌شن (با باز کردن اپ تمدید می‌شه). یادآوری‌های تکرارشونده هم همین‌طور.
- بعد از ریستارت گوشی، پلاگین آلارم‌ها رو دوباره ثبت می‌کنه.
- اندروید حداکثر حدود ۵۰۰ آلارم هم‌زمان می‌پذیره؛ اپ نزدیک‌ترین ۴۰۰ تا رو می‌ذاره.
- یادآوری کلاس‌ها فقط بین «شروع ترم» و «پایان ترم» و خارج از روزهای تعطیلی که در «تنظیمات» ثبت می‌کنی ساخته می‌شه (اگه تاریخ ترم رو خالی بذاری، همیشه فعاله).
- تایمر پومودورو با زمان پایان واقعی کار می‌کنه و پایانش یه نوتیفیکیشن جدا داره؛ با قفل شدن صفحه یا بستن اپ هم از دست نمی‌ره.

### حریم خصوصی
- اپ مجوز اینترنت نداره و بکاپ خودکار گوگل (`allowBackup`) هم عمداً خاموشه؛ پس داده‌ها فقط وقتی از گوشی بیرون می‌رن که خودت فایل بکاپ رو بفرستی.
- تبعیت از دکمه برگشت اندروید: اول بستن پنجره یا زیرصفحه، بعد برگشت به داشبورد و بعد خروج.

## ساخت APK با GitHub Actions

1. یک ریپوی جدید در گیت‌هاب بساز و کل این پوشه رو push کن (شاخه `main`).
2. تب **Actions** ← workflow به اسم *Build Android APK* خودش اجرا می‌شه.
3. بعد از اتمام، پایین صفحه اجرا، بخش **Artifacts** ← `daneshyar-debug-apk` رو دانلود کن (zip که داخلش `app-debug.apk` هست).

### نسخه Release امضاشده (اختیاری، ولی برای آپدیت بدون پاک شدن داده لازمه)
APK دیباگ با کلید موقتی امضا می‌شه که هر بار فرق می‌کنه؛ پس آپدیت روی نسخه قبلی نصب نمی‌شه. برای آپدیت‌پذیر بودن، یک‌بار keystore بساز:

```bash
keytool -genkeypair -v -keystore release.keystore -alias daneshyar \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w 0 release.keystore > keystore.b64      # روی مک: base64 -i release.keystore -o keystore.b64
```

در گیت‌هاب: Settings ← Secrets and variables ← Actions ← New repository secret:

| نام Secret | مقدار |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوای `keystore.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز keystore |
| `ANDROID_KEY_ALIAS` | `daneshyar` |
| `ANDROID_KEY_PASSWORD` | رمز کلید |

با ست شدن این‌ها، workflow خودکار `daneshyar-release-apk` رو هم می‌سازه.

> ⚠️ فایل `release.keystore` و رمزهاش رو جای امن (و چند جا) نگه دار و هرگز داخل ریپو commit نکن. اگه گم بشه دیگه نمی‌تونی آپدیتی بدی که روی نسخه نصب‌شده بشینه.

## نصب روی گوشی
1. فایل APK رو از zip دانلودی دربیار و به گوشی بفرست.
2. روی فایل بزن؛ اگه اندروید پرسید، «نصب از این منبع» رو برای همون برنامه (مرورگر یا مدیر فایل) فعال کن.
3. بعد از اولین اجرا، مجوز نوتیفیکیشن رو Allow کن.
4. از «بیشتر ← تنظیمات» مجوز آلارم دقیق رو چک کن و باتری برنامه رو روی «بدون محدودیت» بذار.

### آپدیت بدون از دست رفتن داده
- نسخه جدید رو با **همون keystore** بساز (و `versionCode` رو در `android/app/build.gradle` یکی بیشتر کن)؛ بعد روی نسخه قبلی نصب کن. داده‌ها می‌مونن.
- اگه قبلاً دیباگ نصب کردی و می‌خوای به release بری، اول بکاپ بگیر، چون امضا فرق می‌کنه و باید نسخه قبلی رو پاک کنی.
- شمای دیتابیس با migration آپدیت می‌شه؛ برای تغییر جدول، یک آرایه جدید به `migrations` در `schema.ts` اضافه کن و آرایه‌های قبلی رو دست نزن.

## تست
```bash
npm test     # Node 22+ لازمه؛ schema و migrationها و SQL اصلی اپ، بکاپ/بازیابی، تقویم شمسی، معدل و تاریخ ترم روی SQLite واقعی اجرا می‌شن
```
این تست‌ها در GitHub Actions هم قبل از build اجرا می‌شن و اگه خراب باشن APK ساخته نمی‌شه.

## اجرای محلی
```bash
npm install
npm run dev          # در مرورگر (ذخیره‌سازی موقت در localStorage، نوتیفیکیشن ندارد)
npm run build && npx cap sync android && npx cap open android   # باز کردن در Android Studio
```

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| نوتیفیکیشن نمیاد | مجوز نوتیفیکیشن برنامه فعال باشه؛ «بیشتر ← تنظیمات ← بررسی مجوز» رو بزن. |
| دیر میاد | آلارم دقیق رو فعال کن؛ باتری برنامه روی «بدون محدودیت»؛ در شیائومی/هواوی Autostart رو روشن کن؛ در سامسونگ برنامه توی «Sleeping apps» نباشه. |
| بعد از آپدیت داده‌ها رفت | احتمالاً با keystore دیگری امضا شده و مجبور به حذف نسخه قبلی شدی. از بکاپ بازیابی کن. |
| خطای Gradle: Java version | Java ‏۲۱ لازمه (در workflow همین ست شده). |
| `cap sync` خطا می‌ده | اول `npm run build` رو بزن تا پوشه `dist` ساخته بشه. |
| صفحه سفید در WebView | `base: './'` در `vite.config.ts` باید بمونه. |
| فونت‌ها نمایش داده نمی‌شن | فونت از `@fontsource/vazirmatn` داخل بسته می‌ره؛ `npm run build` رو دوباره بزن. |

## چیزهایی که هنوز روی دستگاه واقعی تست نشدن
- ساخت APK و رفتار پلاگین SQLite و نوتیفیکیشن روی گوشی واقعی (SQL اپ با تست‌ها روی SQLite معمولی بررسی شده، ولی خود پلاگین اندروید فقط روی دستگاه قابل تست است).
- جای ذخیره فایل بکاپ روی اندروید ۱۱+ و نمایش زیر نوار وضعیت روی گوشی‌های مختلف.
- قفل بیومتریک (اثر انگشت) پیاده نشده؛ قفل فعلی فقط پین است.
- پیوست فایل مستقیم به تکلیف پیاده نشده؛ به‌جاش لینک (درایو و…) ذخیره می‌شه.
